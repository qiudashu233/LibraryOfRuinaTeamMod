# 本地双端测试方案

## 真实 Steam 双端

最接近正式环境的同机方案是运行两个相互隔离的 Windows 系统环境：本机房主和一台有图形加速的虚拟机。两端分别登录不同 Steam 账号，各自有可同时运行《废墟图书馆》的游戏授权，并安装同一 Mod 包、同一原版游戏版本。通过 Steam 的 LOR With Mods 启动，房主进入存档开房，虚拟机端通过房间 ID 加入。

普通 Steam 客户端一次只登录一个账号；两个游戏窗口若复用同一 SteamID，不能形成两个独立大厅成员，也无法验证成员鉴权。Steam 远程同乐共享一个游戏进程，同样不能验证本 Mod 的双客户端连接。虚拟机需要足够 CPU、内存与图形能力；若无法稳定运行游戏，第二台实体电脑更可靠。

## 单账号本地自检

一个账号可以在房主本机检查：Mod 加载、建房、载入存档后读取进度、快照编码与界面显示，以及退出房间后存档哈希是否变化。SteamNetworkingSockets 官方另提供 `CreateSocketPair` 回环连接供网络收发测试，但游戏附带的 Facepunch C# 封装没有公开该方法；若以后加入专门的本地诊断入口，它也只能验证消息收发，不能验证两个账号之间的 Steam 大厅成员鉴权与 Relay 握手。

## 本次问题的复测

协议 v4 将单个 P2P 监听 socket 的虚拟端口改为 `0`，符合 Steamworks 文档建议。之前的协议 v3 使用 `17617`，是否为断线原因尚未经过双端验证。任何真实双端复测都必须让两端使用同一 v4 包。若进度仍未到达客端，在再次启动游戏前分别复制两端 `Player.log`；Unity 再次启动会覆盖上一轮日志。

参考：Steamworks `ISteamNetworkingSockets`、Steam Support 的账号使用说明、Steam Families 并发副本说明。

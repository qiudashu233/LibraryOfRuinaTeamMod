# 本地双端测试方案

## 真实 Steam 双端

最接近正式环境的同机方案是运行两个相互隔离的 Windows 系统环境：本机房主和一台有图形加速的虚拟机。两端分别登录不同 Steam 账号，各自有可同时运行《废墟图书馆》的游戏授权，并安装同一 Mod 包、同一原版游戏版本。通过 Steam 的 LOR With Mods 启动，房主进入存档开房，虚拟机端通过房间 ID 加入。

普通 Steam 客户端一次只登录一个账号；两个游戏窗口若复用同一 SteamID，不能形成两个独立大厅成员，也无法验证成员鉴权。Steam 远程同乐共享一个游戏进程，同样不能验证本 Mod 的双客户端连接。虚拟机需要足够 CPU、内存与图形能力；若无法稳定运行游戏，第二台实体电脑更可靠。

## 单账号本地自检

一个账号可以在房主本机检查：Mod 加载、建房、载入存档后读取进度、快照编码与界面显示，以及退出房间后存档哈希是否变化。现已加入独立的快照编解码测试与 Steam `CreateSocketPair` 本机收发测试。游戏附带的 Facepunch 封装把该方法设为内部接口，Mod 的诊断入口通过反射调用；它只用于诊断，不参与正式 Relay 传输。此项测试不能验证两个账号之间的 Steam 大厅成员鉴权与 Relay 握手。

## 本次问题的复测

协议 v4 将单个 P2P 监听 socket 的虚拟端口改为 `0`，符合 Steamworks 文档建议。之前的协议 v3 使用 `17617`。2026-09-29 的双端日志证明 v4 能建立连接，但房主的旧身份校验主动断开了测试端；协议 v5 改用房间消息校验连接对应的成员。v5 双端连接与校验通过，但客端拒绝快照；协议 v6 修订快照采集并加入详细解码诊断。之后复测必须让两端使用同一 v6 包。若进度仍未到达客端，在再次启动游戏前分别复制两端 `Player.log`；Unity 再次启动会覆盖上一轮日志。

参考：Steamworks `ISteamNetworkingSockets`、Steam Support 的账号使用说明、Steam Families 并发副本说明。

## 单账号自检步骤与结果（2026-09-29）

命令行自检（本机 Steam 已登录，游戏可关闭）：

```powershell
New-Item -ItemType Directory -Path artifacts/local-selftest -Force | Out-Null
dotnet run --project tests/CodecHarness/CodecHarness.csproj --configuration Release -- artifacts/local-selftest/snapshot.bin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/loopback-smoke.ps1 -PacketPath artifacts/local-selftest/snapshot.bin
```

编解码测试直接引用 Mod 的 `ProgressSnapshot.cs`，构造含中文、韩文及英文的 135 关卡、10 楼层、馆员列表和已选关卡的快照。12 项检查涵盖各字段往返、房间 ID 绑定、空包、超长包、截断、尾随字节、错误魔数、错误版本和未列入快照的已选关卡。结果：`PASS: 12 codec checks; snapshot 5552 bytes.`

回环脚本通过游戏附带的 Facepunch Steamworks 和本机 Steam 账号创建两种 socket pair：内存连接及 127.0.0.1 网络回环。每种模式都以 Reliable 发送该 5552 字节快照，并反向发送一次，逐字节比较完整数据。两种模式均为 `PASS`。额外验证了不主动调用 `SteamClient.RunCallbacks()` 时，轮询 `Receive` 仍可完成两种模式收发，符合游戏内 Update 轮询路径。

游戏内可载入存档、创建房间后在 F9 面板点击 `Run local snapshot + loopback self-test`；状态文字和 `Player.log` 中的 `[RuinaCoop] Local self-test` 会显示结果。该入口已编译并安装，尚待用户在游戏画面中点击确认。结果为 `PASS: codec + memory pair + 127.0.0.1 pair, both directions.` 时即代表本机自检通过。离房或退出游戏时会关闭 socket pair。

v5 另有 `Test Steam room messages` 按钮。房主创建房间后点击；`PASS: Steam room message and sender ID.` 说明当前游戏进程能收到带发送者 Steam ID 的房间消息。用户于 2026-09-30 报告此项 PASS。跨设备 P2P 与完整握手仍需双端复测。

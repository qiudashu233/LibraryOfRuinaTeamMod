# 阶段 2：房主进度镜像验证

状态：只读进度原型已通过本机房主显示验证，双端 Relay 镜像验证进行中。当前只在 F9 面板展示；原版关卡界面的接入及实际接待选择尚未完成。

## 本轮实现

- 房主在载入图书馆存档后，从当前游戏模型读取章节、图书馆等级、原版可用关卡状态、已开放楼层和各楼层馆员姓名。
- Steam Relay 在大厅成员之间传输显式字段的版本化快照；房主检查连接者是当前大厅成员，客人检查连接者是原房主。消息限制为 64 KiB，并校验房间 ID、版本、数量和字段长度。
- 房主可在 F9 面板标记“下一关”的计划选择；客人只读地查看该选择。该选择暂不触发原版接待。
- 客人仅保存收到的快照于 Mod 内存，不调用 `LibraryModel.LoadFromSaveData`，不修改关卡解锁或原版存档。

## 游戏程序集核查

- `LibraryModel.GetOpenedFloorList()` 从 `_openedSephirah` 和 `_floorList` 组合读取开放楼层；`LibraryFloorModel.GetUnitDataList()` 返回已开放馆员。
- `StageClassInfo.currentState` 先检查额外解锁条件，再由 `StageClearInfoListModel` 的清除次数与解锁集合判定；状态 `Close` 的关卡不发送。
- `LibraryModel.GetSaveData()` 会遍历库存、卡组、楼层及其他存档模块，故本原型只读取所需字段，不传整个存档对象。
- 本机 Facepunch Steamworks 提供 `CreateRelaySocket<T>`、`ConnectRelay<T>` 和 `Receive`，接收回调需在 Unity Update 内轮询。

## 本机验证结果

2026-09-25，房主在标题主菜单开房时面板正确显示等待存档；点击“继续游戏”进入图书馆后，自动生成进度快照。`Player.log` 记录 `Relay listener ready` 和 `Progress snapshot 1: 135 stages, 10 floors.`；用户确认右侧章节、关卡与馆员正常显示。退出游戏后 `save_slot_1.dat` 的 SHA-256 仍为 `936D205200AFB16602CABD0DCB9C83824103B1179448B7F9C344C51F5DFB7E45`。此结果只验证本机房主读数，尚未证明客端 Relay 同步。

1. 客人进入房间后，右侧显示与房主相同的进度摘要；Relay 连接与快照序号出现在两端日志。

4. 两端测试前后各自的 `save_slot_*.dat` 哈希不变，若游玩期间发生原版正常保存，则应单独记录并判断变化来源。

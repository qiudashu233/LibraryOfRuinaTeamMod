# 阶段 2：房主进度镜像验证

状态：本机房主进度显示通过；v4 双端日志已定位房主主动断开连接的原因。协议 v5 已安装，本机房间消息自检通过，等待双端进度复测。当前只在 F9 面板展示；原版关卡界面的接入及实际接待选择尚未完成。

## 本轮实现

- 房主在载入图书馆存档后，从当前游戏模型读取章节、图书馆等级、原版可用关卡状态、已开放楼层和各楼层馆员姓名。
- Steam Relay 传输显式字段的版本化快照；v5 房主通过随机挑战和房间消息发送者身份确认连接者属于当前大厅，客人连接到房间记录的房主 Steam ID 并等待确认。消息限制为 64 KiB，并校验房间 ID、版本、数量和字段长度。
- 房主可在 F9 面板标记“下一关”的计划选择；客人只读地查看该选择。该选择暂不触发原版接待。
- 客人仅保存收到的快照于 Mod 内存，不调用 `LibraryModel.LoadFromSaveData`，不修改关卡解锁或原版存档。

## 游戏程序集核查

- `LibraryModel.GetOpenedFloorList()` 从 `_openedSephirah` 和 `_floorList` 组合读取开放楼层；`LibraryFloorModel.GetUnitDataList()` 返回已开放馆员。
- `StageClassInfo.currentState` 先检查额外解锁条件，再由 `StageClearInfoListModel` 的清除次数与解锁集合判定；状态 `Close` 的关卡不发送。
- `LibraryModel.GetSaveData()` 会遍历库存、卡组、楼层及其他存档模块，故本原型只读取所需字段，不传整个存档对象。
- 本机 Facepunch Steamworks 提供 `CreateRelaySocket<T>`、`ConnectRelay<T>` 和 `Receive`，接收回调需在 Unity Update 内轮询。

## 本机验证结果

2026-09-25，房主在标题主菜单开房时面板正确显示等待存档；点击“继续游戏”进入图书馆后，自动生成进度快照。`Player.log` 记录 `Relay listener ready` 和 `Progress snapshot 1: 135 stages, 10 floors.`；用户确认右侧章节、关卡与馆员正常显示。退出游戏后 `save_slot_1.dat` 的 SHA-256 仍为 `936D205200AFB16602CABD0DCB9C83824103B1179448B7F9C344C51F5DFB7E45`。此结果只验证本机房主读数，尚未证明客端 Relay 同步。
## 双端首次测试与握手修订

2026-09-28，用户提供的两端截图显示 Steam 大厅已有 2/5 成员，房主已生成快照，但右侧仍为 `Sharing host progress with 0 guest(s)`；客端显示 `Host progress relay disconnected: App_Generic`，没有收到房主进度。房主日志只记录到生成快照。用户提供的客端 `Player.log` 来自随后一次启动，只有 Mod 加载记录，没有加入房间或 Relay 记录，不能据此确定哪一个回调关闭了连接。

Steam 官方把 `App_Generic` 归为应用主动结束连接的代码。因此检查了本 Mod 原先在连接早期立即校验房间成员与远端身份的路径。协议 v3 改为先接受 Relay，最多等待 5 秒确认对端在 Steam 大厅中，确认前不发送快照；客户端也记录连接身份和断开原因。未验证身份或非房间成员仍被拒绝。两端重新打包并安装后需复测，不能把这次修订当作已验证修复。 Steamworks 文档建议只有一个 P2P 监听 socket 时使用虚拟端口 `0`；2026-09-29 将原来的 `17617` 改为 `0`，协议号升至 v4。此项也待双端验证。

完成上述只读原型测试后，再接入原版接待界面、卡牌库存和房主实际关卡选择；这些是阶段 2 完整验收所需内容。

## 单账号自检（2026-09-29）

编解码命令行测试直接编译 `ProgressSnapshot.cs`，以 135 个关卡、10 个楼层和多语言名称构造 5552 字节快照，12 项往返与异常输入检查全部通过。使用游戏自带 Facepunch Steamworks 的 `CreateSocketPair`，同一个 Steam 账号在内存模式与 127.0.0.1 回环模式下，均完成该快照的双向 Reliable 收发和逐字节比较。F9 面板现提供相同路径的手动自检按钮，等待游戏内点击确认。上述结果不能证明真实双账号 Relay 握手已经修复，后续双端复测仍需进行。命令见 `docs/本地双端测试.md`。

## 2026-09-30 双端日志定位与协议 v5

房主 `Player.log` 已生成 `Progress snapshot 1: 135 stages, 10 floors`，随后记录 `Incoming relay connection`、`Host socket connected`，回调身份为 `ip:::`，再由本 Mod 记录 `Relay peer rejected: invalid identity` 并以 `2001` 主动断开。测试端日志相应记录连接成功后以 `2001` 断开。故旧面板中的“等待房主加载存档”不是实际根因；房主存档已加载，快照没发送是因为身份校验在连接建立后立即拒绝了非 Steam ID 形式的回调身份。

协议 v5 保留 Steam P2P 传输，但连接后先发送随机挑战；客端通过 Steam 房间消息回传与挑战、自己的 Steam ID 和房间 ID 绑定的证明。房主只根据房间消息回调提供的发送者 Steam ID 和实时成员列表放行连接，然后发送确认和进度快照。未证明或已离房的连接仍会断开。客端在确认前拒绝快照。双端均须更新到 v5。

本机已通过 12 项快照编解码检查和 10 项挑战及成员绑定检查，Mod 构建为零警告、零错误。独立命令行进程未能创建用于房间消息回环的 Steam 房间，因此改在游戏内加入 `Test Steam room messages`。2026-09-30 用户在房主游戏中点击后报告 `PASS: Steam room message and sender ID.`，证明当前游戏进程的房间消息回调与发送者 ID 可用。完整跨设备握手和进度镜像仍待 v5 双端复测，不把本地检查视为联机已修复的证明。

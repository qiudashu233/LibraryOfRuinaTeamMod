# 阶段4A：首幕初始化原型

记录日期：2026-10-10。基线为v16提交`7329444`，用户已双端确认关卡跳转、角色锁定、对应书页/卡组编辑及准备就绪。当前开发分支为`codex/battle-initialization`。

## 范围

本节点用于验证同一次接待的首幕初始化，不是可出牌的完整合作战斗。首版固定关卡3（尹事务所），两位出战馆员，由房主和一名客人分别控制一位。其他已在房间中的玩家可以旁观，不参与控制者确认。

馆员每人9张战斗书页，XML ID仅1至5。核心书页仅基础1至5、7、9至20及鼠页200001至200003，并且实际有效被动为空；基础书6/8具有特殊被动而排除。敌人为1003/1004，核心书101003/101004，原版卡组为`1,2,3,1,2,3`。这些限制来自本机实际XML与运行时核查，不能仅凭书页名称判断支持。

房主运行真实原版初始化与AI选牌，停在第一幕玩家输入前。客端只显示权威数据，不构建原版BattleUnitModel，不执行本地抽牌、AI、伤害、任务、邀请消耗、奖励或存档。首版客端显示独立首幕验证页面；完整原版战斗演出适配留在后续节点。

## 初始化与失效处理

1. 房主检查当前准备版本和所有控制者就绪，重新采集出战配置，建立唯一战斗会话；从此冻结认领与配装。
2. 控制者确认关卡、邀请书、馆员身份/归属、核心书实例、完整卡组和被动摘要。确认绑定房间、战斗会话、准备上下文及版本；观战确认不阻塞开始。
3. 提交前再次核对真实配置。冻结自身不作为装备变化增加版本；真正配置变化会取消开始。超时、拒绝或控制者断线在提交前返回准备并撤销就绪。
4. 房主消费一次原版加载许可，推进速度骰、抽牌与AI，到首幕输入边界先暂停再采集状态。双方验证完整数据摘要后显示确认结果。
5. 提交后断线、超时、非白名单状态或摘要失败保持暂停，不能按取消准备回滚接待。此受限原型验证结束后需要退出游戏并重新启动；离房不解除原版场景暂停。

使用独立可靠消息，单包上限65536字节、payload上限60000字节；实际首幕数据上限32768字节。先严格检查类型、长度、身份、尾部和SHA256，再原子替换显示状态。重发采用同一会话，重复确认不会再次初始化原版接待；旧连接回调仍受连接对象及代次双重检查。

## 首幕状态契约

配置身份与原版单位索引分开：馆员按准备名单中的稳定身份映射，原版出战单位可能重新编号；敌人按真实UnitBattleData引用映射。双方同名馆员和同名手牌不会因XML ID相同而合并。

首幕编码包括：地图/波次/幕/原版阶段，敌我配置身份和原版索引，float精度体力与阶段体力，混乱/生存标志，光芒及预留/后续恢复值，五个卡牌区域中每个卡实例、顺序、费用及标志，速度骰和敌方卡牌目标/目标骰槽，个人及队伍情绪、情感币和抗性。当前/下一幕/再下一幕buf、当前/待生效被动、情绪能力、个人EGO、替换卡组、卡牌效果和关卡脚本存储均显式采集并按支持范围检查。首版不支持的派生脚本或非空效果队列会拒绝初始化；不能把省略字段的摘要当作完整状态证明。

原版波次从1开始，DTO波次从0开始，采集时显式减一。卡牌先建唯一实例目录，再用五个有序区域引用；原版UseCard同时把同一物理卡加入已用区和保留区，这一重叠合法，其余重复或遗漏引用拒绝。NextRoundPlayPoint=-1、团队上一情绪级1和空keepCard容器等原版正常初值均按真实IL处理。原版还按馆员defaultBookId记录enterBinah，即使已换普通书也可能置位；该身份标志完整传输，其他晚期状态标志仍拒绝。采集失败日志包含有长度上限的阶段/单位数值概况，不输出存档全文。

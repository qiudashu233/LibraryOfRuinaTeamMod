# 阶段 3：接待前角色认领原型

状态：协议 v7 的 F9 认领原型已实现并通过本地编译、状态机测试及房主游戏内操作，等待双端测试。卡组锁、原版接待界面及战斗操作仍未接入。

## 当前流程

1. 房主先在 **Host progress** 页选择下一关，再切到 **Role claims** 页选择一层已开放的楼层。
2. 该楼层的馆员按当前名单位置形成最多五个槽位。房主和客人可认领空槽，也只能释放自己认领的槽。一个玩家可认领多个馆员。
3. 客端请求经已验证的 Steam Relay 连接发送。房主按请求的关卡、楼层、槽位和修订号裁定；过期请求、重复请求、抢已认领槽和释放他人槽均被拒绝。房主广播新的权威归属，客端只展示收到的结果。
4. 换关卡、换楼层或房主馆员名单变化时，旧认领失效。成员离房后，房主可点击 **Release claims of departed members** 清理其认领；不会自动转给房主。

这是接待准备权限的网络原型。当前槽位身份是“选定楼层 + 当前馆员位置”，房主会比较游戏内馆员对象；名单对象变化则清除认领。选择楼层仅作用于 Mod 的 F9 准备面板，不会驱动原版接待界面。认领不阻止原版卡组编辑，不能据此开始联机接待。

## 本地检查

- `dotnet run --project tests/CodecHarness/CodecHarness.csproj --configuration Release`：关卡快照、认领冲突/释放/名单变化、请求与回复编码、房间成员挑战检查通过。
- `dotnet build src/RuinaCoop/RuinaCoop.csproj --configuration Release`：针对当前游戏程序集构建通过，零警告零错误。
- 用户在房主本机确认：进入存档开房、F9 选关、选楼层、认领并释放一个馆员均正常。

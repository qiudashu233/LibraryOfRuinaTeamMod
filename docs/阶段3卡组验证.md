# 阶段 3：卡组编辑与权限锁

记录日期：2026-10-01。开发分支：`codex/stage3-deck-lock`。协议 v8，进度快照格式 v3。这是等待游戏内双端验收的开发测试版。

## 已实现

- F9 的 **Deck editor** 显示房主所选楼层每位馆员的当前战斗书页和可用库存。只有认领者能提交添加或移除请求；固定、锁定及多卡组核心书保持只读。
- 请求经已经认证的 Relay 连接送到房主。房主重新采集状态，检查关卡、楼层、角色归属、认领修订号、卡组与共享库存修订号、请求序号和库存，再调用原版装备规则。普通卡组容量、每种书页副本上限和核心书限制由原版决定。
- 原版 UI、`UnitDataModel`、`BookModel` 和 `DeckModel` 的相关改卡、清空、换装备、应用预设入口都有权限前缀。房主也不能通过普通 UI 改动客人认领的馆员。
- 增删操作如果被原版拒绝、抛出异常或无法生成有效快照，会原地恢复卡组和库存条目及数量。回滚不调用原版存档加载，避免其旧卡 ID 迁移逻辑。库存和卡组只在 Unity 主线程操作。
- 客人每次只提交一个卡组请求，收到对应主机状态后才解锁下一次编辑；确认先到、快照暂时发送失败时，会等待快照重发。超时期间保留锁定，提示离房重进。
- 战斗场景激活时冻结所选楼层的准备操作；返回原版图书馆 UI 后解冻。检测使用 `GameSceneManager.battleScene.gameObject.activeSelf`，避免 `StageController.State` 战斗后不复位的问题。
- 离房或换关、楼层、馆员名单会撤销权限。客人 Relay 断开后，其认领保持锁定并提示房主；房主点击 **Release claims of disconnected members** 后才能重新认领。
- 客端镜像只保存在 DTO 中。客人房间会话期间禁止原版存档及 `latest.dat` 进度记录写入和单人开战；从标题“继续游戏”载入自己的存档仍可使用原版加载路径。游戏设置和 Mod 选择配置可以正常保存。

原版基础无限书页沿用库存 API 的 `x99` 显示。多卡组只展示当前卡组。整数 ID 协议仅支持原版内容；出现 Workshop 书页时相应卡组改为只读。

## 本机检查

在仓库根目录运行：

```powershell
dotnet build src/RuinaCoop/RuinaCoop.csproj --configuration Release '-p:GameDir=D:\game\steamapps\common\Library Of Ruina'
dotnet run --project tests/CodecHarness/CodecHarness.csproj --configuration Release
dotnet run --project tests/DeckGuardHarness/DeckGuardHarness.csproj --configuration Release
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/guard-target-smoke.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/relay-ack-smoke.ps1
```

CodecHarness 覆盖新快照字段、恶意/截断消息、库存争抢、版本失效和认领权限。DeckGuardHarness 用最小游戏替身执行实际前缀与事务代码，检查拒绝返回值、加载/授权作用域、保存保护以及异常回滚。两个 PowerShell 检查使用本机真实游戏和 Mod 程序集验证补丁目标与卡组确认处理。

2026-10-01 最终检查结果：Release 构建 0 警告、0 错误；CodecHarness 通过（快照 5571 字节）；DeckGuardHarness 147 项通过；52 个真实补丁目标与前缀签名、7 个继承字段、加载 finalizer 契约检查通过；编译后 `RelaySession.CompleteDeckReply` 的 14 项确认顺序检查通过。

`guard-target-smoke.ps1` 默认仅核对签名。其可选 `-InstallPatches` 在独立 Windows CLR 中会碰到 Unity 内建调用的 ECall 限制，不能用于证明 Unity 内安装成功；实际加载必须在游戏进程中验收。

这些检查不能替代 Unity 内的 Harmony 加载、Steam 双账号、原版 UI 操作和客人存档哈希验收。游戏内结果尚未提供；v8 不替代已双端验证的 v7 基线。

具体步骤见 [给测试玩家的卡组测试说明](给测试玩家的卡组测试说明.txt)。重点验证：

1. 认领者添加/移除普通书页，两端卡组与有限库存同时更新。
2. 房主通过原版 UI 改动客人认领馆员时被阻止；清空、预设、换核心书和从库存移除已装备书页等入口同样不能绕过。
3. 卡组满、超过副本上限或不符合核心书要求时拒绝，卡组与库存均不变化。
4. 两个馆员争抢最后一张有限书页时仅一个成功；另一端看到最新库存，可以在刷新后重试。
5. 换关、换楼层、换馆员名单、释放及断线清理后的旧权限失效。
6. 客人加载原本存档正常；退出房间后存档文件哈希不变。正常单机游戏导致的保存需单独说明。
7. v7 与 v8 明确拒绝互联。

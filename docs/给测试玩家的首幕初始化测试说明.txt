Ruina Coop v17：阶段4A首幕初始化测试

本包用于检查第一次战斗初始化。房主会进入原版战斗，客端显示独立的首幕数据页面；本版尚不能出牌或结算本幕。
验证结束后，两端退出游戏，再重新启动。房主不能通过退房解除暂停，也暂不支持游戏内安全返回邀请页。

一、安装
1. 两端关闭游戏，备份旧RuinaCoop目录。解压同一个RuinaCoop-stage4A-v17-initialization-test.zip。
2. 将整个RuinaCoop文件夹放入LibraryOfRuina_Data/Mods，替换旧包。不要把Dependencies里的DLL移到Assemblies。
3. 用Steam的LOR With Mods启动并勾选本Mod。F9房间协议应为17；v16不能与v17互通。
4. 房主/客人都载入各自图书馆；房主建房，另一账号加入。客人无需解锁房主关卡。

二、配置（本轮只测固定范围）
1. 房主选择尹之事务所接待，原版关卡ID为3，敌方ID为1003和1004。开始时会检查实际ID，其他接待不会放行。
2. 挑战楼层只选两位出战馆员，房主认领一位，客人认领另一位。使用普通馆员，避免特殊固定核心书和多卡组角色。
3. 馆员每人9张战斗书页，仅允许XML ID 1、2、3、4、5，允许重复。
4. 核心书仅基础ID 1至5、7、9至20，或鼠页200001至200003；实际有效被动必须为空。基础6/8有特殊被动，不支持。若无法判断书页ID，请记录开始时显示的限制原因及双方日志，勿为测试改动存档库存。
5. 完成编辑后回到准备页面，双方点击就绪。任何配装、名单或归属变化都应撤销旧就绪。

三、开始与预期
1. 房主点击原版开始按钮，或“开始首幕初始化验证（结束需重启）”。
2. 页面先显示配置冻结、等待控制者确认，再显示房主初始化首幕。无需退出房间重进。
3. 房主原版场景停在第一幕玩家输入前；双方自动出现“联机首幕·初始化验证”数据面板。
4. 等待双方均显示首幕状态校验通过，比较体力/混乱、光芒、速度骰、手牌/牌库和敌方意图。卡牌显示#实例号，同名牌不能被合并。敌方已选牌可同时出现在已用区与保留区，但应是同一个实例号。
5. 此时不能出牌、撤牌、自动配牌、开始本幕或胜负结算，这是本版的验收边界。

四、取消与失败
1. 配置确认完成前，房主可“取消开始，返回准备”；所有控制者应重新就绪，之后能重新编辑或开始。
2. 使用不支持的关卡、书页、有效被动或人数，应在加载前给出限制原因，不能偷偷进入单机战斗。
3. 配置确认/状态确认有60秒期限。提交前断线或失败回准备；提交后断线、超时或发现不支持状态会保持暂停，不能回滚为准备。
4. 已提交后请直接退出游戏。退房、关闭F9或重建房间都不能恢复这个房主场景；不要尝试继续单机战斗。

五、反馈
1. 验证完成或遇到失败时，退出游戏并先保存两端Player.log，再重新启动（重启会覆盖日志）。
2. 日志默认在%USERPROFILE%/AppData/LocalLow/Project Moon/LibraryOfRuina/Player.log。
3. 反馈双方停在哪一步、限制/暂停提示、所用关卡和书页ID，以及双方日志。重点看[RuinaCoop] Battle init和原版首幕失败信息。
4. 可同时核对客端存档未获得房主进度；安装核验和自动检查不能替代真实双端验收。

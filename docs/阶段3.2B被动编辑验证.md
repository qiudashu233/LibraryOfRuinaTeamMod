记录日期：2026-10-09。用户双端复测确认 v11 已能正常更换核心书页，按已批准方案继续本阶段。开发分支 `codex/passive-editor` 从 `02af724` 接续，房间协议升级为 v12，进度快照格式升级为 v6。

## 交付范围

在联机馆员编辑页点击被动栏、右上“查看/编辑被动”，或当前已装备核心书行的被动按钮，打开游戏原版被动继承弹窗。页面使用房主的实例级来源池、被动槽、已提交继承关系和原版点数预算。每次打开拥有独立的书页、被动和 XML 副本，选择只修改本地草稿；应用时提交完整被动槽与来源书列表，取消丢弃草稿。

只允许修改自己认领馆员的普通核心书。已装备来源书、被他人占用的来源书、有未提交原版草稿或不支持的书不能借用；不自动卸下他人装备或解除其他角色继承。原生被动保留，继承填入原版允许的空槽，撤回继承恢复该槽原生配置。固定、特殊和多卡组书继续后续适配。

原版允许挂靠来源书但尚未继承任何被动，该书仍占来源名额。本协议显式提交最终来源列表，不从被动 ID 列表猜测来源占用。点数读取房主 `GetMaxPassiveCost`，槽位限制、可继承标记与 ID/InnerType 互斥按已核实原版规则校验，不使用客端进度或随机概率检查。

## 数据与局部事务

- `PassiveMirror` 仅读已提交 origin。快照包含原生/当前被动、成本/稀有度/负面标记、来源槽、借出接收者及完整挂靠关系。来源书 token 连接现有核心书实例池，不用房主保存实例 ID 查询客端库存。损坏关系按关联闭包标为不支持，无关书继续可用。
- 每书最多 64 槽，来源最多 4 本；请求最大 977 字节，快照仍限 65,536 字节。被动池过大时整池提示 `PacketLimit`，不静默截断，也不破坏已有卡组和核心书库。
- `PassiveAuthority` 检查准备上下文、馆员稳定身份、目标实例、角色归属、共享修订号、完整来源、空槽、点数、来源名额及重复/同类被动。
- `PassiveTransaction` 再检查真实图书馆、库存与对象关系，捕获原来源和最终来源的并集；释放旧继承后按原版接口构建整组草稿，只对目标及相关来源调用 `ApplyPassiveSuccession`。新来源即使未借出被动，也按原版规则处理卡组与共享库存：当前卡组非空时清空其全部卡组并退卡；当前空而隐藏 stored 卡组非空时，原版保留隐藏卡组。提交后核对实际预期，不扩大原版清空范围。
- 复用扩展的装备 savepoint，覆盖馆员绑定、外观、相关书和被动的 origin/reserved、全部卡组，以及库存引用、数量和顺序。异常或发布前失败恢复原对象；已发布快照成为提交边界，后续显示或传输失败只重试交付，不倒退真实状态。
- 被动、卡组和核心书请求共用资源修订号与等待锁。精确重复的被动请求返回原回执，不再提交；同请求 ID 改变槽位或来源列表被拒绝。客端需同时取得回执和对应修订号的权威快照才解锁。

## 原版弹窗隔离

原版 `SetData/SetDataOnly/Open/InitReservedData`、添加/移除、应用/取消和编译生成的延迟确认回调全部接管。房间内未绑定独立草稿的原版入口拒绝打开，避免全书库重置 reserved。单机原版全库应用、成就与保存回调不用于联机提交。

库存查询在独立模型中解析；私有 XML 副本使用房主属性，不改共享静态 XML。选择事件绑定页面代次和槽位身份，旧按下事件、旧确认和已退出模型不能提交到新页面。房主资源/认领修订号改变后保留草稿供查看并锁定应用，提示取消重开；换关、楼层、馆员、核心书、撤权或离房则关闭草稿。

关闭时恢复原版页面字段并释放强引用，弱标记继续保护退休模型。离房后新的真实单机 `SetData/SetDataOnly` 恢复原版编辑；旧联机模型和自有确认回调保持失效。

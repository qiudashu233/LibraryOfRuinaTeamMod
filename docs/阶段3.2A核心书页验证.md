## 交付范围

从原版卡组页面点击馆员核心书页，或右上“查看/更换核心书页”，进入原版核心书库页面。库存为房主的实例级书库，包含其他楼层装备占用、默认/特殊书和被动来源占用原因。同名书通过会话实例 token 区分，不用房主实例 ID 查询客端真实书库。

只允许为自己认领的馆员选择空闲普通核心书。可以换出自己的默认书；不能将默认书、他人装备书、被动来源占用书、未应用草稿书或特殊/固定/多卡组书作为普通目标。已提交且 origin/reserved 一致的接收方继承可以随书保留，不会因为“带继承被动”就一律禁止换书。

房主运行实际 `EquipBookForUI(target, false, false)`，按原版重新装备规则处理卡组，切换原版中性/书页外观，并同步实际核心书、属性、有效被动、卡组和共享库存。原版该方法即使成功也返回 `false`，本轮通过实际引用、owner、卡组结构和库存后置条件判断结果。

成功保留同一馆员认领，更新书实例及显示代次。受控重绑必须核对完整核心书库存、普通书类型、本馆员装备归属、ID/实例和支持标记；不能借此进入特殊书编辑。旧按钮、角色切换、刷新前按住的装备按钮和已关闭页面的迟到事件均不能提交新角色/书的修改。ACK 与相应版本快照都到达后才解除等待，核心书和改卡共用一端一个待确认修改限制。

被动配置编辑、礼物、固定/特殊/多卡组、清空/预设及真正合作接待继续按后续节点实施。核心书库的速度、情绪、抗性等未同步字段使用占位，有效被动显示不开放继承编辑；原版继承来源详情面板暂隐藏，避免查询客端真实书库。

## 实现与隔离

- `EquipmentMirror` 从房主真实书库、装备列表和现有 `_floorList` 采集，不调用会创建缺失楼层的 `GetFloor`。核心书最多 2048 实例、每份最多 64 张卡/64 个有效被动；整个快照不超过 64 KiB。过大或采集失败时整份核心书库存不可用并显示原因，原有卡组数据继续保留，不把截断库存当成可用资源。
- `EquipmentProtocol/EquipmentAuthority` 校验房间、关卡/楼层、馆员稳定身份、认领和装备修订号、旧/目标书 token、共享占用和冻结。客端数据仅用于显示和请求，最终从房主最新真实模型裁定。
- `EquipmentTransaction` 快照并原位恢复角色核心/外观书、旧/新/关联被动来源书的 owner、全部卡组、有效被动及 origin/reserved 数据、真实卡牌库存和书库对象/集合顺序。原版拒绝、异常、后置条件失败或完整快照提交前失败都会回滚，不通过加载整份存档恢复。
- `RelaySession` 将核心书及卡组资源合并到同一 `DeckRevision`。精确重复请求重放原结果，不再换书；同请求 ID 携带不同内容拒绝。提交后网络发送失败不回滚已确认的权威模型。超时继续锁住编辑，重新加入后读取权威状态。
- `NativeEquipmentEditor/NativeDeckModels` 使用独立书页显示对象和永久镜像标记，不注册进客端真实书库。原版页面的库存查询、关闭保存、教程、书签、被动及释放入口被替换/限制；客端保存保护继续有效。

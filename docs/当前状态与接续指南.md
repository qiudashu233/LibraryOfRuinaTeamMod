# Ruina Coop 当前状态与接续指南

记录日期：2026-10-01。此文已更新至卡组开发测试版；各阶段的详细记录见文末链接。

## 先看结论

- **已双端验证的版本仍是协议 v7 的角色认领原型**，代码基线为 `feature/stage3-role-claims` 的 `c82a846`。本机游戏安装仍是 v7，回退包 `dist/RuinaCoop-stage3-v7-claims-test.zip` 保留。
- **当前开发分支为 `codex/stage3-deck-lock`，协议 v8**。已接回旧 WIP 并补齐卡组/库存快照、主机请求校验、客端路由、原版权限补丁、局部回滚和保存保护。本机构建与自动检查通过；游戏内加载和双端卡组验收尚未完成。旧 `feature/stage3-deck-lock` 的 `1e5e12f` 仍是不能直接安装的历史半成品。
- v8 新增 F9 卡组编辑与原版改卡权限锁。选关和角色认领仍是 F9 准备计划，尚不能通过 Mod 发起或同步原版接待，合作战斗尚未实现。
- 产品范围仍是房主加至多四名客人、原版游戏加本 Mod。客人只临时查看房主进度，不需要自己解锁关卡，也不应获得永久存档进度。

排障过程中的关键结论：标题主菜单尚未载入图书馆存档时，`Progress waiting` 是预期状态；点击“继续游戏”进入图书馆后房主才能采集进度。早期客端显示 `relay disconnected: ... 2001` 时，双端日志表明房主把 Relay 回调中的 `ip:::` 当作无效 Steam ID 而主动断开；协议 v5 改用 Steam 房间消息挑战确认成员，房主游戏内的 `Test Steam room messages` 曾显示 `PASS: Steam room message and sender ID.`。随后 v5 能连接，但客端报 `Rejected an invalid host progress packet`；协议 v6 对采集字段与解码约束做一致性校验，之后双端进度镜像及选关同步通过。不要把旧截图中的“等待存档”当作上述两次故障的根因。

单账号自检曾完成快照编码/解码，以及 Steam `CreateSocketPair` 的内存与 `127.0.0.1` 双向可靠收发。这些只证明本机数据与回环路径；跨账号房间、成员鉴权和 Relay 同步仍以实际双账号结果为准。

## 如何运行现有 v7（回退基线）

1. 两台设备使用同一 `RuinaCoop-stage3-v7-claims-test.zip`。关闭游戏，将包中的整个 `RuinaCoop` 文件夹放到各自游戏的 `LibraryOfRuina_Data\Mods\` 下；确认 `Mods\RuinaCoop\StageModInfo.xml` 存在。不要同时勾选其他 Mod。
2. 在 Steam 选择 **LOR With Mods** 启动，只勾选 **Ruina Coop (Development)**。房主先点击“继续游戏”进入自己的图书馆存档，再按 **F9** 创建房间。客人可用 Room ID、公开房间列表或 Steam 邀请加入，不需要解锁房主的关卡。
3. 双方在 F9 的 **Host progress** 页核对房主章节、关卡、楼层、馆员；房主选择 `Selected next stage`。再到 **Role claims** 页选楼层、认领及释放馆员，核对两端归属。
4. 测完从 F9 离房并正常退出。此版本只验证 F9 原型；不要将它用于真正的联机接待或卡组权限测试。

双人逐步操作另见 [给测试玩家的认领测试说明](给测试玩家的认领测试说明.txt)。若失败，在**再次启动游戏前**分别复制两端 `%USERPROFILE%\AppData\LocalLow\Project Moon\LibraryOfRuina\Player.log`，记录失败时的 F9 截图、双方房间人数和 Mod 包哈希。客人存档不应被本 Mod 修改；后续完整回归可在测试前后比较双方 `save_slot_*.dat` 哈希，原版正常保存则需单独说明。

## 如何构建和本机自检

环境：Windows、Steam 版《废墟图书馆》、.NET SDK、.NET Framework 4.6 引用程序集。以下命令在仓库根目录 `D:\code\ai\libariayTeam` 运行，且应位于当前 `codex/stage3-deck-lock` 分支。本机游戏路径为 `D:\game\steamapps\common\Library Of Ruina`。重建 v7 时另行切换已验证分支，勿把两个版本的目录包混用。

```powershell
dotnet build src/RuinaCoop/RuinaCoop.csproj --configuration Release '-p:GameDir=D:\game\steamapps\common\Library Of Ruina'
dotnet run --project tests/CodecHarness/CodecHarness.csproj --configuration Release
dotnet run --project tests/DeckGuardHarness/DeckGuardHarness.csproj --configuration Release
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/guard-target-smoke.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/relay-ack-smoke.ps1
```

2026-10-01 v8 复核结果：Mod 构建 **0 警告、0 错误**；CodecHarness 输出 `PASS: snapshot, claim/deck authority and protocols, and lobby-auth checks; snapshot 5571 bytes.`；DeckGuardHarness **147 项检查通过**。实际 DLL 的 **52 个补丁目标签名、7 个继承字段及 14 项卡组确认顺序检查通过**。这些覆盖协议、权限、库存校验和事务回滚，不等于 Unity 内补丁加载或双账号游戏测试。

需要重新生成**目录包**时，在确认分支后运行：

```powershell
pwsh -File scripts/pack.ps1 -GameDir 'D:\game\steamapps\common\Library Of Ruina'
```

脚本写入 `dist/RuinaCoop`；ZIP 需另行生成。当前分支打出的是 v8。关闭游戏后可运行 `pwsh -File scripts/install-local.ps1` 把该目录包安装到本机游戏。安装脚本会先将旧 `Mods\RuinaCoop` 备份到 `artifacts/install-backups`，再替换 Mod 目录；不会改动原版游戏程序集。本轮保留本机 v7 安装，v8 的安装和双端操作见 [卡组测试说明](给测试玩家的卡组测试说明.txt)。

需要复核单账号快照与 Steam socket pair 回环时：

```powershell
New-Item -ItemType Directory -Path artifacts/local-selftest -Force | Out-Null
dotnet run --project tests/CodecHarness/CodecHarness.csproj --configuration Release -- artifacts/local-selftest/snapshot.bin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/loopback-smoke.ps1 -PacketPath artifacts/local-selftest/snapshot.bin
```

这条回环路径要求本机 Steam 环境可用。只有一个 Steam 账号无法在同一会话里形成两个不同的大厅成员；真实双端验收仍需第二个账号和设备或独立的 Windows 环境。

# 阶段 3.1：原版卡组页面开发记录

日期：2026-10-07 至 2026-10-08。开发分支 `codex/native-deck-editor`，由已验证基本卡组功能的 v8 节点继续开发。用户已批准实施 [原版卡组界面接入方案](原版卡组界面接入方案.md)。

## 实现范围

- 游戏内常驻“联机准备”入口，认领/释放与编辑/查看馆员；打开真正的原版馆员卡组页，并在原版左侧角色列表切换。
- 双方页面绑定独立的显示馆员、核心书、卡组和库存，不将房主 DTO 导入客端图书馆、书库或保存列表。房主最终修改仍落在自己的真实馆员上。
- 原版单卡点击转为现有 Add/Remove 请求；等待权威快照和确认后刷新，房主库存变化也更新页面。搜索、筛选和详情使用原版组件。
- 显示绑定包含房间、关卡、楼层、稳定馆员身份、核心书实例与修订号。切角色、收到新状态、换楼层与退出后撤销旧显示事件；请求完成另发状态通知。
- 协议 v9、快照格式 v4，补充有界的 HP、混乱、有效被动和普通原版外观字段，不传 SaveData 或纹理槽。
- 核心书更换、被动继承、清空/预设、跨书籍占用查询暂不可编辑。固定及多卡组书页只读。
- 退出时恢复 UI 选择、临时可见性、教程标记与原有渲染绑定；退出房间先清理页面，再撤销客端保存保护。

完整 Steam 发送方法仅检查 IL 的前置校验顺序；执行的是共用纯校验函数及确认状态方法。上述程序集检查不安装 Harmony 补丁，不运行 Unity 渲染和页面生命周期。本轮未启动游戏；实际补丁加载、动画、焦点、头像、筛选位置、返回恢复及双端库存仍需游戏实测。

普通原版外观包含皮肤、脸部件、颜色与身高；礼物装饰未同步，HP/混乱由房主计算后发送。未同步的速度、情绪和抗性等显示保持隐藏或占位，不能借用客端属性。

双方先进入自己的图书馆再打开联机卡组页。进入标题页房间不代表原版编辑 UI 已初始化。完整测试步骤见 [给测试玩家的原版卡组测试说明](给测试玩家的原版卡组测试说明.txt)。

v8 原 ZIP 和历史分支保留，作为基本卡组功能回退基线。当前新页面尚无用户游戏内验收反馈。
